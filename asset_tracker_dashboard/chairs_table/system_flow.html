Status Workflow How a deployment request moves through the system
📝
Pending
Staff submits a deployment request with chair colors + quantities, table shapes + quantities, purpose, location, and duration.
🚚
Deployed
Equipment is delivered and set up. Status updated manually by staff.
⏰
For Retrieval
Retrieval date is reached. System can auto-update status from "Deployed" to "For Retrieval".
📦
Retrieved
Equipment is returned. Quantities go back to available inventory.
📅
Long Term
For extended deployments (e.g., municipal events, long-term government functions).
⚠️
Overdue
Status is "For Retrieval" and retrieval date has passed. System highlights overdue records.

Database Schema 3 tables for chairs & table tracking
equipment_types
ColumnTypeNotes
id PKINTAuto-increment
categoryENUM('Chair','Table')Distinguishes chairs from tables
subtype_nameVARCHAR(50)"White", "Blue", "Round", "Rectangle", etc.
display_nameVARCHAR(100)"White Monoblock Chair", "Round Table"
total_qtyINTTotal inventory count for this subtype
available_qtyINTCurrently available count

Pre-populated data: White/Blue/Red/Black chairs, Round/Rectangle/Square tables.

deployments
ColumnTypeNotes
id PKINTAuto-increment
nameVARCHAR(255)Requestor name
contact_noVARCHAR(30)+639 format
purposeVARCHAR(255)Wake, Fiesta, Birthday, etc.
locationVARCHAR(255)Barangay / venue
addressVARCHAR(500)Full address
statusENUM('Pending','Deployed','For Retrieval','Retrieved','Long Term')Default: 'Pending'
dateDATEInstallation date
retrieval_dateDATEScheduled retrieval date

Allows mixed deployments: e.g. White Chairs x10 + Round Tables x3 in one request.

UI Components Deploy Modal — Subtype Selection with Quantity
📝 Instead of a visual grid (like tents): The Deploy Equipment modal will have two sections:
  • Chairs Section: Dropdown to select color (White/Blue/Red/Black) + Quantity input
  • Tables Section: Dropdown to select shape (Round/Rectangle/Square) + Quantity input
  • Plus button to add multiple rows of different subtypes in one deployment
Auto-Update Mechanism Cron-based status transitions
⚙️ How it works: Every 5 minutes (via Windows Task Scheduler), update_status_duration.php runs and checks:
  • Deployments where status = 'Deployed' AND retrieval_date = CURDATE()
  • Moves them to status = 'For Retrieval'
  • Sliding 60-second JS interval on the frontend for real-time feel
